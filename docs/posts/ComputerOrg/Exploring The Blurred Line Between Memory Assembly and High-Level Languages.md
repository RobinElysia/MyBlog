# 探究：内存、汇编与高级语言之间的模糊地界

## 前言
&emsp;很少会有人打着热爱的名号去研读计算机科学相关的书。但很不巧的是，每一个计算机从业者都应该好好学学计算机科学，这并非幌子，而是更深入的理解和知晓其中的实现原理，这也是我本篇文章的核心部分，即：“高级语言屏蔽了哪些我们不知道的东西？”。

&emsp;这部分我将参考《计算机组成原理》一书的第三、四章节，详细介绍高级语言是如何在内存和汇编上实现变量、函数、方法和参数传递的，除此以外还有一些关于C、Java与Python的详细深入。话不多说，直接开始！

## 内存

&emsp;在最开始，计算机科学会让我们首先接触内存，这是一个极其精明的决定，因为在后续的“第一门编程语言”学习中，你将无处不在的接触内存，思考中的内存数据。但是现在，我们需要先来回忆一下内存到底长什么样：

&emsp;对于一般的，我们的内存是一个随机访问的线性存储空间，它相当于一张白纸，并不存在特定的结构，不过，我们倾向于在数据结构的基础上来讲内存。什么意思呢？我们可以把内存组织成“栈”（它类似于23年山东物理高考[](https://zhuanlan.zhihu.com/p/659029941)的那道盘子题。其原理是：先近来的数据后出去（因为数据压入了底下），后进来的数据先出去（因为数据在最上边），因为出口只有顶部）、或者组织成“队列”（类似于买东西的队列，先排队的先支付，出口是底部）。

![](/assets/img/ComputerOrg/0ed74f48c7f543c722eaf3104ff13fc1.png)

&emsp;当然，我说了这是一般的，被组织成数据结构的内存，我们真正讨论的是一个加载了数据的内存，也就是被“_start”初始化后的内存，它不仅是结构化的内存，还是有数据的内存。一个较为广泛流传的图是来自ELF标准文件：

![](/assets/img/ComputerOrg/3d97565b0d7f52b416bd5ca5a8273913.png)

这张图的描述与我曾见在[计算机当中的“进程”](http://localhost:8080/posts/OSDesign/%E6%B5%85%E8%B0%88%E8%AE%A1%E7%AE%97%E6%9C%BA%E5%BD%93%E4%B8%AD%E7%9A%84%E2%80%9C%E8%BF%9B%E7%A8%8B%E2%80%9D.html)这篇文章中提到的“execve之后：一个进程的原初状态”ELF一致。这到底是什么？我们暂且不知道，但可以肯定的是，这些信息是关于当前进程的，我们这篇文章的任务就是解析内存中的这些信息。

&emsp;注：我使用了信息而不是数据，因为信息=数据和程序，这部分包含程序本身（代码段）。
